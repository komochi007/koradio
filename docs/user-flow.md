Radio 输入先由活动 AI 大脑结合最近对话和当前节目摘要路由为闲聊、澄清、单曲推荐、多首推荐或完整节目。闲聊只追加文本回复；歧义只追加澄清问题；单曲推荐先按歌名、主艺人和版本标签筛出原唱录音室原版，再在 15 秒总预算内依次验证最多 3 条同曲同艺人候选，只有拿到真实音频引用才返回可播放卡片。网络、超时或限流等瞬态解析失败只自动重试一次；全部原版候选失败时保留自然说明和“重新获取 / 换一首”，不展示 `PLAY NOW`，也不静默换成翻唱、纯音乐或其他歌曲。用户明确请求推荐/挑选 3～5 首时默认返回最多 5 张已通过音频解析的策展卡片。高置信节目请求仍由本地路由保证进入节目流程，但必须调用活动 AI 大脑生成自然首句和完整结构化意图；AI 不可用或输出无效时不创建节目任务。推荐检索必须包含歌曲名和原唱主艺人，后端统一排除翻唱、Cover、现场、混音、伴奏与加速/降速等变速版本，除非用户明确点名该版本。用户说“围绕某首歌规划歌单/节目”时进入完整节目流程，原曲作为第一首；“类似”在该语境下描述相似维度，不得把节目降级为推荐卡片。只有纯粹的“还有哪些、再推荐一些”等追问才按推荐处理。单曲和多首卡片都提供 `PLAY NOW`、`PLAY NEXT`，作为不改写 Program、播放历史或持久队列的临时 DJ 点播。对话按 Profile 持久化最近 50 个 turn，切换 Profile 隔离上下文，清空需二次确认。

规划上下文中的音乐库覆盖当前 Profile 最多 1,000 首可播放曲目摘要，即个人完整候选库。活动 Planner（Codex 或 DeepSeek）读取结构化场景、`EffectiveTaste`、近 20 期节目歌曲、当前时间和偏好；Radio 的完整对话仅用于意图路由与重试上下文，不作为未筛选的 Planner 候选。完整节目目标为 8～12 首：简单场景默认 8 首，条件较多、活动较长或有明确情绪弧线时由 Planner 选择 9～12 首。默认库内/库外各半，奇数时库外多一首；库内符合硬约束的候选不足时可由库外补足并提示，明确“只探索新歌”或“只听库内”则分别成为严格来源约束。结构化听歌意图额外携带锚点歌曲、相似维度、`languageScope`、`regionScope`、`vocalMode`、类型、场景、情绪、能量、节奏显著度、注意力等级、风格排除项、探索倾向和年代。柔和、舒缓、平和、安静办公、不抢注意力收敛为低刺激、克制节奏与专注/背景聆听；轻律动只允许温和脉冲。当前听歌意图优先于 Taste，Taste 仅作跨艺人、年代与邻近曲风探索的特征级线索。Backend 按 intent 顺序解析最多 16 个候选并统一执行来源、原始发行年代、可播放性、原版、人声与语种校验：Library ID 必须属于当前上下文，Discovery 每个关键词最多入选一首非库内结果，且必须给出原唱主艺人并与搜索结果校验。纯音乐模式独立接受无实质歌词的正式器乐、配乐与器乐编配，不因通用替代版本规则误杀；仍拒绝翻唱、Karaoke、Type Beat、AI 和非官方伴奏。最近 3 档或过去 24 小时内的歌曲硬禁重复；第 4～10 档的同曲、近期艺人和高频艺人优先延后，只有合规候选不足才回退复用。明确点名歌曲或艺人可覆盖对应去重。指定华语、中文、欧美、英语、日语或韩语时自动要求可验证主唱歌词，拒绝纯音乐、主题配乐、`Type Beat`、BPM/调式或制作信息、稀疏时间轴散文和无法证明实质主唱的候选。用户发送“重试一下/再试一次”时，系统沿用最近一次非重试的节目场景重新规划，不把重试短句当成新场景；找不到可继承场景时先澄清。补选后少于目标数量，或显式硬约束无法满足时，新节目失败并保留旧节目，同时说明具体原因。

完整节目在已有节目时不立即覆盖播放状态：任务和阶段由持久 Job 保存，Radio 返回时通过活动任务 Snapshot 恢复“正在规划”的对话状态；成功后新节目保存为待切换状态，离开 Radio 或重启后仍可读取。其他一级页面显示轻量“节目准备中 / 新节目已就绪”入口，可一键回到 Radio。旧节目继续播放，新节目默认在当前曲自然结束时切换，用户可按 `SWITCH NOW` 立即切换；切换后才更新当前节目指针。Programs 历史立即保留新节目，但其是否已在播由当前节目指针和待切换状态共同决定。

## 6. 关键异常分支清单

```text
[Launchpad 唯一 Koradio 入口]
  -> 联网读取可信 origin/main
  -> 当前提交一致：继续启动 bundled Local Service
  -> 读取活动 AI 大脑配置与本地服务状态
     ├─ 本地服务可用：进入 Radio
     └─ 本地服务不可用：进入 Settings 修复本地服务或配置
  -> 发现新提交：在应用拥有的缓存源码中构建并验证候选
     ├─ 成功：原位替换 /Applications/Koradio.app，重新启动最新版
     └─ 失败：保留当前 app 与用户数据，但不打开旧版
  -> 网络或远端检查失败：显示本地启动状态窗口，不启动服务、不打开旧版产品页；用户可重试
  -> 服务探测和健康检查并行执行，仍只选择 49373-49383 范围内最低可用端口
  -> 产品页面只在 Electron 桌面窗口中打开，不创建第二个 PWA 安装图标
```

## 6.1 运行模式与数据来源

```text
[Production / macOS Electron shell]
  -> 默认 LIVE
  -> Radio / Library / Settings 显示 LIVE
  -> Library 总数和策展候选排除 DEMO 数据

[Development / Test / CI / 显式 Demo]
  -> 使用 Mock Provider
  -> 页面显示 DEMO MODE
  -> 节目与音乐写入 originMode=mock
```

历史 Demo 节目保留并标识，不自动删除；Live 当前节目为空时不得从历史 Demo 节目自动恢复。

## 6.2 删除历史节目

```text
[节目卡片或详情更多菜单]
  -> 点击“删除节目”
  -> 展示节目标题与不可恢复说明
  -> 用户确认
     ├─ 删除失败：保留卡片并显示可重试错误
     └─ 删除成功：发布 program.deleted 并刷新相关页面
          └─ 若为当前节目：停止播放、释放租约、清空当前节目、返回 Radio 无节目态
```

```text
[本地服务未连接]
  -> 显示独立“本地服务未连接”异常页
  -> 已打开或缓存的 PWA 展示 ○ OFFLINE、重试、只读 Settings、启动说明和脱敏诊断
  -> 配置、密钥、测试和迁移控件全部禁用
  -> 连接成功后返回 Radio

[阻断错误]
  -> 跨页面或跨区块错误进入界面中央的可关闭错误卡片
  -> 卡片不自动消失、不阻断播放，并提供恢复入口：重试 / 前往 Settings / 修改输入 / 降级继续
  -> 字段校验仍在相关字段附近内联显示；完整离线页与致命错误页保持原结构

[未配置核心服务]
  -> 场景发送被阻止
  -> 用户看到缺少活动 Planner 配置
  -> 跳转 Settings
  -> Codex 保存命令，或确认 DeepSeek 隐私提示并保存 Keychain key 后测试

[Qwen3-TTS 不可用或模型未安装]
  -> 阻止新节目提交
  -> 保留用户输入和旧节目
  -> 提供模型安装、修复或重试入口

[Planner 规划失败]
  -> 保留用户输入
  -> 显示“点击重试”
  -> 不自动切换另一个 AI 大脑；用户重试、修改场景或前往 Settings

[用户请求“重试一下/再试一次”]
  -> 解析最近一次非重试的节目场景与结构化听歌意图
  -> 沿用原语言、地区、人声、锚点与类型要求重新规划
  -> 没有可继承的节目场景时先请求用户补充描述

[语言、地区或人声约束不足]
  -> 后端拒绝不满足硬约束的候选，不以 Taste 语言比例静默放宽
  -> 显示库内曲目、语言/地区、人声、原版或音频可播性不足的具体原因
  -> 保留旧节目并提供重试或修改输入入口

[Track intent 无结果或不可播]
  -> 系统按顺序跳过该 intent
  -> 不从其他 Profile 随机补位
  -> 全部 intent 失效时提示换描述
  -> 不创建空节目

[TTS 失败]
  -> helper 超时或掉线时自动恢复并重试同一段一次
  -> 第二次失败才使本次生成失败
  -> 保留用户输入和旧节目
  -> 提供重试和修复入口

[TTS 无分句时间戳]
  -> Detail Sheet 保留串讲文本
  -> 按文本长度估算当前句高亮
  -> 播放不受影响

[歌词缺失]
  -> Detail Sheet 显示“暂无歌词”
  -> 波形和播放不受影响

[主题切换失败]
  -> Settings 回滚到上一次主题
  -> Radio 和 Detail Sheet 保持原主题
  -> 提示“主题保存失败”

[DJ 语言切换]
  -> Settings 保存 zh-CN 或 en-GB
  -> 下一次 Planner 规划使用新语言
  -> 当前已生成节目不强制重写串讲

[DeepSeek 首次启用]
  -> Settings 显示场景、EffectiveTaste、历史和库内摘要将发送到 DeepSeek，并提示可能产生费用
  -> 用户明确确认隐私提示
  -> 通过 Keychain 写入 API key，选择 Flash 或 Pro
  -> 下一次生成使用 DeepSeek；当前节目和运行中的任务不变

[DeepSeek 切回 Codex]
  -> Settings 先用候选 Codex 做连接与可执行性检测
  -> 检测通过才保存并启用 Codex
  -> 检测失败则保留当前 Provider，并显示具体原因
  -> 不删除已有 DeepSeek key，除非用户明确点击删除

[DeepSeek 密钥删除]
  -> 用户明确确认删除
  -> Keychain 删除成功后显示未配置
  -> 若当前活动 Provider 是 DeepSeek，则阻止下一次生成并提示配置 AI 大脑或重新设置 DeepSeek

[播放失败]
  -> 当前曲标记不可播放
  -> 自动尝试下一首
  -> 全部失败时提示重新生成

[反馈保存失败]
  -> 播放不中断
  -> UI 状态回滚或提示未保存
  -> 用户可稍后重试

[Reduce Motion]
  -> 关闭持续波形和大部分转场动画
  -> 保留 PLAYING / SPEAKING / THINKING 等文字状态
  -> 播放和流程不受影响
```

## 7. 开发前校准验收矩阵

| 场景 | 前置条件 | 关键动作 | 必须结果 |
|------|----------|----------|----------|
| 首次启动 | 无 bootstrap 与数据目录 | 启动 Local Service | 自动选择并创建可写 OS 应用数据目录，不要求用户手填路径 |
| 桌面启动更新 | Launchpad 存在唯一 `/Applications/Koradio.app` | 打开 Koradio | 必须联网确认 `origin/main`；已是最新才启动，发现更新则本机构建、验证、原位替换后重新启动；失败时不打开旧版 |
| 菜单栏快捷控制 | Electron 已加载 CommonJS preload bridge 且存在当前播放快照 | 点击 Koradio 品牌图标 | 原生菜单显示当前状态、曲名/艺人和上一首、播放/暂停、下一首；“显示 Koradio”置前主窗口，“退出 Koradio”退出应用；关闭主窗口时图标随应用退出 |
| TTS 缺失 | 活动 Planner、网易云可用，设备不支持、Qwen 模型未安装或 helper 缺失 | 提交合法场景 | 本次生成不提交节目，保留旧节目并提供语音修复入口 |
| 模型首次安装 | macOS 15+ arm64，模型未安装 | 在 Settings 点击下载 | 显示约 1.84 GiB 下载进度；完整性通过后原子启用 Serena/Ryan |
| 模型下载失败 | 网络中断、空间不足或校验失败 | 等待安装结束 | 清理应用拥有的 partial，允许重试；已有节目与歌曲播放不受影响，新节目暂不可用 |
| 完全离线 | Local Service 不可达，PWA 已打开或缓存 | 进入 Settings | 仅只读展示启动说明、脱敏状态和重试；所有配置、测试与迁移控件禁用 |
| DeepSeek 首次启用 | 用户选择 DeepSeek 且隐私提示未确认 | 在 Settings 阅读并确认提示、保存 Keychain key | 确认前不启用；确认后只影响下一次生成 |
| DeepSeek 切换 | 已有节目或 generation job 正在运行 | 切换 AI 大脑或模型 | 先完成新 Provider 连接与认证检测；通过后当前节目和运行中任务保持不变，下一次生成再执行完整规划契约校验 |
| DeepSeek 失败 | key 缺失、认证/余额/限流、网络或 schema 错误 | 重试或切回 Codex | 本次生成失败并保留旧节目，不自动 fallback |
| 迁移成功 | 目标目录为空且可写 | 发起迁移 | 暂停任务/播放并存 checkpoint，备份复制校验，原子切换 bootstrap 后重启；旧数据保留 |
| 迁移回滚 | 任一迁移阶段失败 | 等待任务结束 | bootstrap 继续指向旧目录，恢复旧数据运行，不自动删除任何目录 |
| 播放中生成 | 旧节目正在播放 | 提交新场景 | 旧节目继续；失败保持不变；成功提交后保存旧 checkpoint、停止旧时间线并原子切换 |
| Profile 切换 | 旧 Profile 正在生成或播放 | 选择新 Profile | 取消旧任务并丢弃迟到事件，保存并停止旧播放，再加载新 Profile |
| 双标签接管 | 标签 A 持有租约 | 标签 B 申请接管 | A 先存 checkpoint 并停止；B 获得新 epoch 后才能播放；续约 `2s`、过期 `5s` |
| 反馈撤销 | 已存在喜欢、不喜欢或节目收藏 | 执行撤销 | 追加对应 removed 事件，不覆盖旧事件，界面由最新有效事件投影 |
| Taste 重建 | 已有自动投影、人工规则与可选学习起点 | 回放学习起点之后的反馈事件 | 可重建 `TasteProjection`，正常重建不覆盖 `TasteOverrides`；显式应用蓝图时才清空 overrides 与旧 projection，并保留历史反馈事实 |
